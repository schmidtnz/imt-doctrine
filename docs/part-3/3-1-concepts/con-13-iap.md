# CON-13 Incident action plans

The incident action plan ({term}`IAP`) puts MBO into practice: a concise, forward-looking plan for one operational period that balances probability, detection, survivability, hazards, urgency and the consequences of being wrong. The planning function leads it, with input from every function.

- **Urgent searches**: deploy first and back-capture the IAP. Uncertainty is not a reason for delay.
- **Protracted searches**: write the IAP before teams are briefed and deployed.
- **Handovers**: never hand over without an IAP for the next period.

## Building an IAP

1. **Set the operational period first**, allowing for travel and debrief. For example, a 10-hour period might be 2 hours travel, 4–6 hours searching, 2 hours return and debrief. Searching much longer than 4–6 hours degrades POD.
2. **Set prioritised SMART objectives**, typically covering search, safety, management and investigation.
3. **Develop the plan**: objectives (what), strategies (how), tasks (who).
4. **Task only to objectives.** If a new task emerges, change the plan formally rather than tasking ad hoc.
5. **Debrief and feed back** into the next IAP.

Use a simple one-page IAP per operational period, filed with that period's tasks and debriefs, so the record builds period by period.
